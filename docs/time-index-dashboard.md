# 競走馬ごとのタイム指数ダッシュボード

`/time-index` で馬名を部分一致検索し、保存済みのタイム指数を競走馬ごとに確認する。
ヘッダーの「タイム指数」、出馬表の馬名、全走一覧の馬名から開ける。

## 検索と履歴の取得

- 初期表示ではDBへ問い合わせず、馬名の入力を案内する。
- 検索候補は `HorseTimeIndex.horse_name` の重複を除いて作る。1件なら直接表示し、複数なら選択する。候補は20件まで表示する。
- 選択後の履歴・集計は馬名の完全一致で取得する。競走馬名は変わらない前提で、競走馬IDの追加やpredictor側の変更を必要としない。
- `Race`・`Entry` との結合は履歴取得の条件にしない。`Race` にない過去の走も表示するが、レース詳細へのリンクは保存済みのレースに限る。
- 検索語・馬名・表示方法・絞り込み・ページ番号はURLに保持する。
- 重複パラメータ、100文字を超える検索語や条件、不正な日付・距離・信頼度ではDBへ問い合わせない。

## 馬別の表示と集計

馬を選んだ直後は、その馬の収録全期間と、全走データと同じ最新の基準バージョンを使う。
別バージョンの同じ走を混ぜて集計しない。画面とURLに適用中のバージョンを持たせる。

サマリーには指数あり走数／収録走数、前走指数、直近5走平均、平均・最高指数を表示する。
「前走」は選択条件に合う最も新しい走を指す。算出不可でも、古い走の値で置き換えない。
直近5走平均は選択条件内の新しい5走だけを対象にし、指数を算出できた件数を併記する。`null` は分母から外し、0は有効な指数として扱う。

サマリー・推移・走別履歴には同じ期間と条件を適用する。
競馬場別・芝ダート別・距離帯別の表では、比較する軸だけ絞り込みを外し、ほかの条件は固定する。
距離帯の平均は、距離ごとの有効件数で重み付けする。少数でも条件を自動で広げない。

推移は直近100走までを取得し、古い順に描く。算出不可の走は欠測として線を切る。
省略がある場合は件数を示す。全履歴は50件ずつのページ送りで確認する。
日付は保存日付のままUTCで整形し、更新日時はJSTで表示する。

## 全走データと既存URL

「全走データ」は `/time-index?view=all` から開く。従来の一覧・分布・絞り込みを残し、期間未指定時は最新開催日から1週間を既定にする。
従来の `racecourse` や `start` などの条件だけを持つURLも全走画面として扱う。
`horse` クエリは馬別画面を開き、完全一致で見つからない場合は部分一致の候補検索へ進む。
全走一覧から馬を開くときは全走画面の期間を持ち込まず、その馬の全期間を表示する。

## 実装と確認

入力検証・表示用の計算は `src/app/lib/horseTimeIndexDashboard.ts`、DBアクセスは `src/app/lib/horseTimeIndexData.ts` に置く。
DB側で集計し、ブラウザへ全履歴を一括転送しない。既存の取得・表示部品を再利用し、スキーマは変更していない。

`npm test` はDBをモックし、検索・集計・画面のサーバー描画を検証する。実データでの手動確認は次の順で行う。

1. 馬名の一部を検索し、候補から馬を選ぶ。該当なしの案内も確認する。
2. 期間や競馬場を変更し、サマリー・推移・履歴が同じ条件になることを確認する。
3. 条件別の表で比較軸だけが外れ、履歴のページ送り後も選択した馬と条件が維持されることを確認する。
4. 出馬表の馬名と、全走データの一覧から馬別画面を開く。
5. 算出不可、指数なし、少数データを確認し、ライト／ダーク・モバイル幅で表示を確認する。
